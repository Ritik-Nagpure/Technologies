# GENERATION RULES

## File Structure
- One file per top-level index section: `01 - Overview.md`, `02 - Core Concepts.md`, ...
- Plus one `index.md` at the root linking to all files.
- If a section exceeds 1500 lines, split into `Part 1` / `Part 2`.
- Sub-topics in the index become `## ` headers inside the file.
- Sub-sub-topics become `### ` headers.

## Per Sub-Topic Depth (mandatory for every item in the index)

For each concept, cover — in this order, skipping only what truly does not apply:

1. **What** — one-paragraph precise definition
2. **Analogy** — real-world comparison to build intuition
3. **Why it exists** — the problem it solves
4. **How it works** — internal mechanism, not just API
5. **Code example** — working, commented, realistic
6. **Wrong vs right example** — if a trap exists
7. **Production usage** — where it appears in real systems
8. **Failure modes** — what breaks and why
9. **Trade-offs** — table when comparing options
10. **When to use / when not to**
11. **Key takeaways** — 3-5 bullets the reader must remember
12. **Trick questions** — 2-3 per topic with answers

## Code Rules
- Every concept gets at least one runnable snippet.
- Use the natural language of TECH (JS/TS for React/Node, SQL for Postgres, YAML for K8s).
- Realistic examples (real variable names, real APIs), never `foo`/`bar`.
- Comment non-obvious lines.
- Show expected output where useful.

## Interview Q&A File (12)
- 60+ questions organized by level: Foundation, Understanding, Senior, Debugging, System Design, Architect, Scenario.
- Every answer explains reasoning, includes code when relevant, names trade-offs.
- Add a "Trap Questions" section — 10+ questions with why they trap and the correct answer.

## Mastery Checklist File (13)
- Ladder: Explain → Visualize → Implement → Use → Measure → Debug → Break → Recover → Compare → Choose → Design → Defend → Teach
- 3-5 checkboxes per rung, specific to TECH.
- End with "When to Move On" and "Return Conditions".

## Tone
- Senior-engineer level. Assume the reader knows JS/TS, git, and has built apps.
- Simple language, no jargon without explanation.
- No motivational filler. No emojis. No "let's dive in".

## Output Format
For each file, output:

## Truncation
If output risks truncating:
- Finish the current file completely.
- End with: `CONTINUE? Reply "continue" for the next batch.`
- On "continue", resume from the next file.
